= 0.Neovim必了解概念

在正式开始之前，有一些重要概念以及基础知识需要学习。**一定要先读完本篇再看后续篇幅！**

IMPORTANT: Neovim本身是一个Vim的分支，但后来Neovim逐渐引入了不少新特性。虽然如此，它还是保留着大量Vim的特性。 +
本文档不需要你有Vim基础，你完全可以直接上手Neovim以及本文档。但一定要记住这一点。



== 0.1.Runtimepath

Neovim的配置文件存在于runtimepath中。runtimepath就是Neovim加载配置文件的路径。runtimepath可以存在多个，你可以自由修改它。 +
runtimepath的默认常见路径包括：

* Linux/MacOS: `~/.config/nvim`
* Windows: `~/AppData/Local/nvim`

TIP: `~` 是当前用户的**家目录**。在Linux中一般是 `/home/用户名` ，在MacOS中一般是 `/Users/用户名` ，在Windows中一般是 `C:/Users/用户名` 。

NOTE: Neovim插件的本质其实也只是配置文件。包管理器一般会帮你为插件自动添加runtimepath。

Neovim的配置文件格式比较自由。在runtimepath中需要一个 `init.lua` 或 `init.vim` 作为配置入口。
既然你都用Neovim了，那当然就要拥抱Neovim带来的Lua支持了，所以本文档[underline]##只包含使用Lua进行配置的详解##。

NOTE: `.vim` 格式的配置文件是Vim的原生配置文件，Neovim也保留了它，但同时引入了完整的Lua支持，且比 `.vim` 更强大。 +
总之，在使用Neovim时，把 `.vim` 忘掉吧。Lua才是Neovim主场。~(除非你是从Vim迁移过来的)~

NOTE: 当 `init.lua` 和 `init.vim` 同时存在时，Neovim默认会忽略掉 `init.vim` ，~__以及没人会同时用这俩对吧__~

Neovim会在启动时运行 `init.lua` 。一般情况下，我们都只在 `init.lua` 里添加 `require` 语句引用其他配置文件（以及一些特殊的玩意），而不是直接将配置放在这里面。
除 `init.lua` 以外，Lua配置文件一般都存放在 `./lua` 目录里。

在使用 `require` 语句时，括号内可以__“使用 `.` 代替 `/` ”__，且无需添加文件扩展名。
同时，可以直接忽略 `./lua` 目录，Neovim会自动在该目录里寻找配置文件，不需要加上 `lua.` 。 +
例如（这个样例参考下面那颗文件树），想要引用 `./lua/plugins/plugin1.lua` ，就可以直接使用 `require(plugins.plugin1)` ，省略了路径中的父文件夹 `lua/` 和文件后缀 `.lua` 。

文件树大概长这样：

 runtimepath
 │
 ├─lua
 │ ├─plugins
 │ │ ├─plugin1.lua
 │ │ └─plugin2.lua
 │ ├─config
 │ │ ├─something.lua
 │ │ └─someotherthing.lua
 │ └─(your_own_config)
 └─init.lua

除了 `init.lua` （和 `./lua` ）以外，所有的配置都是完全自由的（只要你引用对了）。比如，你可以自由创建文件/夹，自由命名它们，以及自由修改内容。
但是注意，**要保持你自己的配置风格**，否则配置文件管理起来就会特别麻烦。你自己的配置风格由你自己决定，但一旦确定了就要严格遵循。
否则你就是故意给自己找麻烦。
[line-through]~除非你是大懒虫~



== 0.2.模式

模式同样是Vim继承下来的产物，但这种说法似乎并不太合适，因为Neovim本来就完全保留了Vim的使用模式。

模式，是指你当前的控制模式。常见的模式有以下几种：

* NORMAL
* INSERT
* COMMAND
* VISUAL

**NORMAL**，顾名思义，是常规控制光标位置的模式。在没有操作的情况下，Neovim一启动就会进入NORMAL模式。 +
在NORMAL模式下，可以通过各种操作移动光标位置，这里就不细讲了，会在 [underline]##1.常用操作## 一篇中详解。

**INSERT**，即“插入模式”，你可以理解为更改文件内容的模式，类似于普通GUI文件编辑器默认的情况。在INSERT模式下可以自由地更改文件内容。 +
进入INSERT模式的方法有多种，会在 [underline]##1.常用操作## 一篇中详解。

**COMMAND**，命令模式，用于输入控制命令。不少操作都会在该模式下完成。 +
依旧会在 [underline]##1.常用操作## 一篇中详解。

**VISUAL**，选择模式。该模式可以选择一部分文本并对它们进行部分操作，比如删除。
还是会在 [underline]##1.常用操作## 一篇中详解。

NOTE: 虽然VimAPI没有直接提供相应的API用于创建新的模式，但可以使用多个VimAPI组合达到创建新的模式的效果。包括模式显示名称。



== 0.3.缓冲区、窗口、标签页

这是3个重要但较为抽象的概念。 +
最简洁的说法是，**缓冲区是内存中已被加载的内容，窗口是实际显示缓冲区的区域，标签页是一个或多个窗口的集合。**

* **缓冲区**是内存中已经被加载的内容，通常是文件。通常来说，打开一个文件后，Neovim就会新建一个缓冲区将文件内容存放进去。
* **窗口**是显示缓冲区的一块区域，一个标签页内可以创建多个窗口。窗口可以显示的缓冲区没有限制，你可以多个窗口显示同一个缓冲区。
* **标签页**是多个窗口的集合，一个标签页内可以创建多个窗口。哪怕跨标签页，窗口可以显示的缓冲区也还是没有限制的。



== 0.4.快捷键

Vi系编辑器的快捷键与其他软件略有不同。

=== 0.4.1.“操作+对象”

这是Vi系编辑器一种独特的快捷键方式。
例如， `dw` 代表 删除(d) 一个单词(w) ， `dd` 代表 删除 一整行。 +
值得注意的一点是，这种操作并不需要将两个键同时按下。只需注意先后顺序即可。

=== 0.4.2.Leader键

Leader是Vi系编辑器中的一个独特按键。自定义的额外按键一般会与Leader键配合。
默认是 `/` 键，但很多人习惯设为 ` ` 也就是空格键。 +
例如，你可以设置 `<leader>s` 为保存， `<leader>f` 为查找。

=== 0.4.3.按键映射

在Vi系编辑器中，自定义按键映射采用一种较为独特的写法。 +
两个并排的字符代表连续键入它们（且不需要同时按下），例如 `dd` 可以按两下 kbd:[D] 键触发。 +
这里的字符分大小写，大写字符可以按住 kbd:[SHIFT] 键入。 +
Ctrl这样的修饰按键也有特殊写法，例如 `<C-v>` 代表 kbd:[CTRL+V] ， `<A-s>` 代表 kbd:[ALT+S] ， `<M-s>` 代表 kbd:[META+S] (效果通常与Alt修饰符相同)， `<D-a>` 代表 kbd:[COMMAND+A] (MacOS专用)。 +
值得注意的是，修饰符组合键需要同时按下才可触发。 +
Leader键表示为 `<leader>` 。

=== 0.4.4.数字前缀

Vi系编辑器有时允许输入数字再按下快捷键进行操作。最典型的是 `5w` ，它代表移动5个单词。
又比如 `15j` 代表向下移动15行。这种用法一般会与相对行号配合。
